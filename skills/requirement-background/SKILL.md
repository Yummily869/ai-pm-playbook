# 需求背景

需求背景不是一段描述，是一段**为什么值得做的具体论证**。

---

## 这个 skill 解决什么

我刚开始写需求文档时，需求背景是这么写的：

> 随着 AI 大模型技术的快速发展，视频创作领域正迎来变革。用户对高效创作工具的需求日益增长，我们希望通过引入大模型能力，提升用户的创作效率和体验。

评审会上被问了四个问题：

1. 「现在模型有什么发展，为什么提出现在做？」
2. 「这个和我们已有的一键成片什么关系？会不会打架？」
3. 「这个是用户的真实需求吗？为什么非要用大模型？模板方案不行吗？」
   

回去改的时候我才意识到问题在哪：**我写的那段话，把「视频创作」换成「客服」「电商」「教育」，句子依然通顺。** 一段可以套用到任何产品上的需求背景，等于没写。

判断标准就这一条：**把行业名换掉，这段话还成立吗？成立就说明写得太泛。**

后来的做法是把范围一层层收窄，写成四层加一个收口：

```
① 市场层  → 为什么是现在（不是去年，也不是明年）
② 团队层  → 为什么是我们做、放在哪里（不是别人，也不是别的位置）
③ 用户层  → 具体是谁、什么场景、用户痛点是什么
④ 竞品层  → 别人怎么做的、我们应该向哪些看齐又能打哪个空档
─────────────────────────────
收口     → 为什么必须用大模型，而不是传统方案
```

## 执行流程

### Phase 0 · 解析输入 + 一次性确认信息

**第一步：从用户输入里解析出这四件事。** 用户没说全的，先推断；推断不出来的，在输出开头标注为「假设」。

| 要素 | 例子 |
|---|---|
| 功能是什么 | 智能剪辑：从长视频自动识别高光，生成可分发的短片 |
| 面向谁 | C 端普通用户 / C 端创作者 / B 端商家 |
| 哪个平台 | 快手快影 / 美团商家端 |
| 素材形态 | 视频 / 图像 / 对话 / 结构化数据 |

**第二步：只问一个问题。**

> 「你手上有没有这个功能相关的现成资料？比如相关功能的使用数据、用户反馈或访谈记录、已有的竞品分析。有的话直接给我，我会用在公司层和用户层；没有也没关系，我会跳过公司层，市场层和竞品层我自己联网调研。」

**规则：**

- **只问这一次。** 用户答「没有」→ 直接进入 Phase 1，公司层整节输出 `⚠️ 缺少内部资料，本节待补`，**不再追问**。
- 用户答「有」并给了资料 → 资料用于 Phase 2 和 Phase 3。
- **市场层和竞品层不问用户**，由本 skill 联网调研（见 Phase 1 / Phase 4）。

---

### Phase 1 · 市场层：为什么现在做

**这一层必须联网调研，不允许凭印象写。** 至少完成前两项：

| 调研动作 | 怎么做 | 要拿到什么 |
|---|---|---|
| 查市场与趋势 | 联网搜索「{品类} 市场规模 报告 {年份}」 | 规模数字 + 增速 + 报告出处 |
| 确认技术阈值 | 搜索对应模型的版本发布说明、能力榜单、评测对比 | 能力「从 X 变成 Y」的具体变化，不要只写「能力提升」 |
| 看用户自发内容 | 用浏览器打开抖音 / 快手 / 小红书，搜场景关键词 | 相关内容的播放量、笔记量，佐证这个需求真的有人在做 |

**写法要求：**

1. 判断的是**有没有某个阈值刚被跨过**：

| 阈值类型 | 表现 |
|---|---|
| 模型能力 | 某项能力从「勉强能看」变成「可交付」 |
| 成本 | 单次成本降到能商业化的量级 |
| 用户认知 | 用户从「不信 AI 生成」变成「主动找 AI 工具」 |

2. **必须写清「在此之前为什么不行」。** 这一句是挡「为什么现在做」追问的关键，也是最容易漏的一句。
3. **必须写能力边界**（现在做不到什么），并据此裁剪本期范围。把限制写出来，「为什么不做 XX」就变成了共识，而不是需要临场解释的东西。
4. **必须写市场潜在需求**

参考写法（脱敏后）：

> 视频生成模型在近期跨过了两个能力阈值：
> ① **可控性**——从「文生视频只能碰运气」到支持视频参考，可指定运镜和节奏，这让「按参考视频复刻」第一次在技术上成立；
> ② **一致性**——多视角主体参考让商品在视频里保持形态稳定。
>
> 在这两个能力之前，视频生成只能做氛围片，做不了带货片。
>
> 当前模型的限制：支持最多 3 段视频输入，总时长 ≤15 秒；长叙事、多人物一致性还不稳定。
> 所以本期只做「短时长、单主体」的场景，长剧情不在范围内。

### Phase 2 · 公司层：放在哪、会不会打架

**用户提供了内部资料就写，没提供就整节跳过**，只留一行：

> ⚠️ 本节缺少内部资料（现有功能数据 / 用户反馈），以下位置判断为公开信息推断，建议补齐后再定稿。

要回答三个问题：

**Q1. 新功能插在现有产品链路的哪个位置？从哪个入口进？**

**Q2. 会不会和现有功能打架？** 这是最实际的风险，列一张表：

| 打架方式 | 具体表现 |
|---|---|
| 抢入口 | 两个功能抢同一个坑位，老功能数据下滑 |
| 认知混淆 | 用户分不清「智能剪辑」和「一键成片」的区别 |
| 能力重叠 | 解决同一个问题，维护成本翻倍 |

参考写法：

> - **能力差异**：模板是固定坑位填素材，做不到根据素材内容编排故事线；这个功能是基于内容生成叙事
> - **用户分层**：模板服务「有明确成品预期」的用户，这个功能服务「有素材但不知道怎么剪」的用户
> - **入口**：不抢模板入口，独立入口并行
> - **上线后要盯**：模板功能的使用量会不会下滑

最后一行「上线后要盯什么」最有价值——它把一个「可能有风险」变成了「有人负责观察」。

**Q3. 我们有什么别人没有的条件？**（数据、用户规模、现有链路的衔接优势）

### Phase 3 · 用户层：别写抽象用户

❌ 反面写法：

> 用户在剪辑视频时觉得麻烦，希望有更高效的方式。

这句话没有场景、没有具体动作、没法验证。

✅ 正确写法：**至少拆 2-3 个角色**，每个角色写「什么情况下 → 遇到什么 → 结果是什么」，结果尽量写到「**因此没有发生什么**」：

> **角色 A：有素材但不会剪的普通用户**
> 场景：旅行回来手机里 50 段素材，想发条 vlog
> 障碍：不知道从哪段开始剪、不知道配什么文案、套模板和素材内容不搭
> 结果：**素材在相册里躺着，最后什么都没发**
>
> **角色 B：会剪但缺创意的创作者**
> 场景：日更压力下要快速出多条
> 障碍：操作没问题，但每天想文案和结构很耗精力
> 结果：产出频率受限于创意，不是受限于剪辑速度

写完这几个角色往往会发现，**它们要的其实是几个不同的产品**，方案设计时就不会在几种诉求之间摇摆。

**痛点的深浅，决定了机会的大小：**

| 层次 | 举例 | 信息量 |
|---|---|---|
| 表层 | 「操作太麻烦」 | 几乎所有产品都能这么说，没有信息量 |
| 中层 | 「要跳 5 个页面才能换一张图」 | 能指向具体优化 |
| 深层 | 「因为麻烦，用户直接放弃了，素材永远躺在相册里」 | **这个才指向真正的机会** |

深层痛点有个特点：**它描述的是「没有发生的事」**。而没有发生的事不在任何数据看板上——用户没进入功能，就不会有埋点。所以这类痛点只能靠用户访谈或自己观察，光看数据看不到。

**有内部资料时**，从访谈记录、用户反馈里抽取证据，每条痛点后面挂一句原始引用。
**没有资料时**，基于场景推断，并在该条后面标 `（推断，待访谈验证）`。

### Phase 4 · 竞品层：推动机，不是列功能

❌ 功能对照表（竞品 A 有什么、竞品 B 有什么）只有信息，没有结论。

**这一层同样必须联网调研：**

| 调研动作 | 怎么做 |
|---|---|
| 找竞品 | 搜索「{品类} 产品 对比」，或去应用商店搜同类功能 |
| 拿事实 | 打开竞品官网 / 版本发布说明 / 体验文，确认它的具体设计选择（入口位置、一次生成几个、是否收费） |
| 看用户评价 | 搜「{竞品名} 难用 / 吐槽 / 对比」，从差评里找它主动放弃的地方 |

**写法：推演他们为什么这么设计。**

> **竞品 A**：把 AI 剪辑放二级入口，且默认只生成 1 个结果
> **我猜的动机**：单次成本高，1 个结果是成本控制；放二级入口说明他们对效果没信心，不愿意用主入口流量冒险
> **对我们的意义**：如果我们要放主入口，得先把成功率做到某个水平；生成多个候选会明显推高成本，要算一下值不值
>
> **竞品 B**：只做模板套用，不做内容理解
> **我猜的动机**：模板成本极低、结果可预测，是稳妥的选择
> **他们放弃了什么**：处理不了「素材和模板不匹配」的情况
> **我们的机会**：这正是我们要打的——基于内容生成叙事，而不是把素材塞进固定坑位

规律：**差异化最好建立在「竞品主动放弃的地方」，而不是「我们想做得更好」。** 后者只是愿望，前者是判断。

**每段竞品分析后面必须有一句「所以我们的选择是」。** 没有这句的分析直接删掉。

### Phase 5 · 收口 + 组装 + 自检

**收口：为什么必须用大模型。**

这是 AI 需求文档和普通需求文档最不一样的一节，也是被问得最多的。

❌ 「传统方案不够智能」——没有任何信息量。
✅ **说清传统方案在结构上做不到什么**：

> **模板 + 图层方案的结构性问题**：
> 模板的本质是「预设固定坑位，把素材填进去」，这意味着：
> - 坑位数量和顺序是**写死的**，没法根据素材实际内容调整
> - 没法判断「哪段素材更适合放开头」
> - 没法根据画面内容生成匹配的文案
>
> **核心矛盾是：模板不理解素材「讲了什么」，所以没法编排「怎么讲」。**
> 而用户要的恰好是「帮我把这堆素材讲成一个故事」，这需要内容理解能力——这是模板在结构上不具备的，**不是做得不够好**。

「不是做得不够好，是结构上不具备」是关键句。

**再主动说清楚哪里不用大模型：**

> 需要说明的是，这条链路不是全都靠大模型：
> - **片段边界判断**：比较机械的判断，小模型就够，成本是大模型的 1/10
> - **字幕排版、转场渲染**：规则可以完全覆盖
> - **素材格式校验**：普通工程手段
>
> 只有「内容理解」和「叙事编排」是大模型不可替代的。

主动划出不用大模型的边界，说明你在算成本，而不是在追技术热点。

**组装输出**：按 [输出格式](#输出格式) 拼成完整章节。
**自检**：过一遍 [自检清单](#自检清单)，不通过的项要么补，要么在输出里标出来。

## 各层最容易犯的错

| 层 | 常见错误 | 改法 |
|---|---|---|
| 市场层 | 只写「市场很大」「技术很成熟」 | 写「哪个阈值刚被跨过」+「在此之前为什么不行」 |
| 市场层 | 只写能做什么，不写不能做什么 | 补能力边界，并据此裁剪本期范围 |
| 公司层 | 不写会不会和现有功能打架 | 列打架方式表 + 写「上线后要盯什么」 |
| 用户层 | 写一个抽象用户 | 拆 2-3 个角色，写场景 → 障碍 → 结果 |
| 用户层 | 痛点停在「操作麻烦」 | 推到「因此什么事没有发生」 |
| 竞品层 | 列功能对照表 | 推动机，每段收一句「所以我们的选择是」 |
| 收口 | 说传统方案「效果不够好」 | 说它在结构上做不到什么 |
| 收口 | 全链路都要用大模型 | 主动写出哪些环节不该用 |

## 自检清单

- [ ] 把行业名换成别的领域，这段话还成立吗？（成立 = 写太泛，重写）
- [ ] 市场层写清了「在此之前为什么不行」吗？
- [ ] 写了能力边界，并据此裁剪了范围吗？
- [ ] 公司层说清了会不会和现有功能打架，以及上线后盯什么吗？（无资料是否已标注跳过）
- [ ] 用户至少拆了 2-3 个角色，而不是一个抽象用户吗？
- [ ] 痛点写到了「因此什么事没有发生」这一层吗？
- [ ] 竞品层每段都有「所以我们」吗？
- [ ] 竞品层的事实（入口位置、生成数量、是否收费）是查证过的，还是凭印象？
- [ ] 收口论证的是传统方案「结构上做不到」，而不是「效果不够好」吗？
- [ ] 主动写了哪些环节不用大模型吗？
- [ ] 所有标为「假设 / 推断」的条目都显式标出来了吗？

## 我还没搞清楚的

- **竞品动机的推演基本靠猜**，我没有验证过猜得对不对。公开信息只能看到「它这么做了」，看不到「它为什么这么做」。有没有更可靠的方法？
- **用户角色拆到几个合适？** 我拆过 5 个，写完发现方案又开始摇摆了，感觉 2-3 个是上限，但没有依据。
- **市场层的数字引用到什么程度算够？** 引用第三方报告的数字，评审有时会说「这个口径不对」，但自己算又算不准。
