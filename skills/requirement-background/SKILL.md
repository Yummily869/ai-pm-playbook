# 需求背景

需求背景不是一段描述，是一段**为什么值得做的具体论证**。

---

## 这个 skill 解决什么

我刚开始写需求文档时，需求背景是这么写的：

> 随着 AI 大模型技术的快速发展，视频创作领域正迎来变革。用户对高效创作工具的需求日益增长，我们希望通过引入大模型能力，提升用户的创作效率和体验。

评审会上被问了四个问题：

1. 「现在模型有什么发展，为什么提出现在做？」
2. 「这个和我们已有的一键成片什么关系？会不会打架？」
3. 「这个是用户的真实需求吗？为什么非要用大模型？模板方案不行吗？」
   

回去改的时候我才意识到问题在哪：**我写的那段话，把「视频创作」换成「客服」「电商」「教育」，句子依然通顺。** 一段可以套用到任何产品上的需求背景，等于没写。

判断标准就这一条：**把行业名换掉，这段话还成立吗？成立就说明写得太泛。**

后来的做法是把范围一层层收窄，写成四层加一个收口：

```
① 市场层  → 为什么是现在（不是去年，也不是明年）
② 团队层  → 为什么是我们做、放在哪里（不是别人，也不是别的位置）
③ 用户层  → 具体是谁、什么场景、用户痛点是什么
④ 竞品层  → 别人怎么做的、我们应该向哪些看齐又能打哪个空档
─────────────────────────────
收口     → 为什么必须用大模型，而不是传统方案
```

## 执行流程

### Phase 0 · 解析输入 + 一次性确认信息

**第一步：从用户输入里解析出这四件事。** 用户没说全的，先推断；推断不出来的，在输出开头标注为「假设」。

| 要素 | 例子 |
|---|---|
| 功能是什么 | 智能剪辑：从长视频自动识别高光，生成可分发的短片 |
| 面向谁 | C 端普通用户 / C 端创作者 / B 端商家 |
| 哪个平台 | 快手快影 / 美团商家端 |
| 素材形态 | 视频 / 图像 / 对话 / 结构化数据 |

**第二步：只问一个问题。**

> 「你手上有没有这个功能相关的现成资料？比如相关功能的使用数据、用户反馈或访谈记录、已有的竞品分析。有的话直接给我，我会用在团队层和用户层；没有也没关系，我会跳过团队层，市场层和竞品层我自己联网调研。」

**规则：**

- **只问这一次。** 用户答「没有」→ 直接进入 Phase 1，团队层整节输出 `⚠️ 缺少内部资料，本节待补`，**不再追问**。
- 用户答「有」并给了资料 → 资料用于 Phase 2 和 Phase 3。
- **市场层和竞品层不问用户**，由本 skill 联网调研（见 Phase 1 / Phase 4）。

---

### Phase 1 · 市场层：为什么现在做

市场层要同时站住两只脚，**缺一只都不成立**：

```
需求侧：这件事本来就有人想做吗？现在他们在用什么笨办法做？（潜在需求）
              ×
供给侧：模型刚跨过什么阈值，让这件事第一次做得成？（能力阈值）
─────────────────────────────────────────
两者的交集 = 现在这个时间窗口
```

只写供给侧，是「有锤子找钉子」——评审会问「模型能做，但用户要吗」。
只写需求侧，是「这需求一直都在」——评审会问「那为什么去年不做」。

**这一层必须联网调研，不允许凭印象写。**

| 调研动作 | 怎么做 | 要拿到什么 |
|---|---|---|
| **需求侧·规模** | 搜「{品类} 市场规模 报告 {年份}」「{人群} 数量 统计」 | 规模数字 + 增速 + 报告出处 |
| **需求侧·笨办法** | 浏览器打开抖音 / 快手 / 小红书，搜「{场景} 怎么做」「{场景} 教程」 | 教程类内容的数量与播放量——有人专门教，说明有人专门愁 |
| **需求侧·未被满足** | 搜「{现有方案} 太麻烦 / 不好用」，看评论区和问答帖 | 用户原话，比任何推断都有说服力 |
| **供给侧·能力阈值** | 搜对应模型的**官方发布说明**（不要用二手解读），看版本间差异 | 「从 X 变成 Y」的具体参数变化 |
| **供给侧·成本** | 查 API 定价页 | 单次生成成本，以及它和客单价 / 广告收益的比值 |

---

#### 需求侧：潜在需求怎么写

**潜在需求不是「市场很大」，是「有多少人正在用笨办法做这件事」。**

三种证据，按说服力从低到高：

| 证据类型 | 例子 | 说服力 |
|---|---|---|
| 行业报告数字 | 「短视频电商 GMV 规模 X 万亿，增速 Y%」 | 低。说明池子大，不说明这个需求存在 |
| **替代行为** | 「搜『商品视频怎么拍』，教程类内容 X 万条，头部条播放量 Y 万」 | 中。有人愁才有人教 |
| **手工成本** | 「商家找达人拍一条带货视频报价 X 元、周期 Y 天；中小商家一个月上新 Z 个品，全拍拍不起」 | **高。这是需求的价格标签** |

最后一类最有用，因为它直接给出了产品的价值上限：**你的功能值多少钱，取决于它替掉了多少手工成本。**

> ⚠️ 数字必须有出处。查不到就写「未查到公开数据」，**不要估算后当事实写**——评审时被追问口径，估算出来的数字一定站不住。

---

#### 供给侧：能力阈值要写到参数级

❌ 「视频生成模型能力大幅提升」——换成任何一年都成立。
✅ **写清楚哪个版本、变了哪个参数、因此什么产品形态第一次成立。**

| 阈值类型 | 判断标准 |
|---|---|
| 模型能力 | 某项能力从「勉强能看」变成「可交付」 |
| 成本 | 单次成本降到能商业化的量级 |
| 用户认知 | 用户从「不信 AI 生成」变成「主动找 AI 工具」 |

**参考写法（模型能力阈值）：**

> **Seedance 2.5（2026-07-31 发布）打开了「完整叙事」：**
>
> | 参数 | 2.0 | 2.5 | 因此第一次能做什么 |
> |---|---|---|---|
> | 单次生成时长 | 15 秒 | **30 秒，且支持多轮延长** | 15 秒只够一个氛围片段；30 秒能装下铺垫→推进→转折→收尾，短剧、教学内容第一次成立 |
> | 参考素材上限 | 有限 | **30 张图 + 10 段视频 + 10 段音频** | 多主体群像（如一段乐队演出，十几个人物各自保持形象和声音稳定）第一次可控 |
> | 编辑能力 | 重新生成 | **时间戳定向编辑、绿幕编辑** | 从「抽卡，不满意重抽」变成「哪段不对改哪段」，单条成本模型完全改变 |
>
> 在 30 秒和多轮延长之前，任何需要讲完一件事的内容都只能拆片段再人工拼接，衔接处的主体漂移是拼接方案无法解决的——**这不是效果不够好，是 15 秒的上限决定了它做不了叙事。**
>
> **MiniMax H3（2026-07 发布）打开的是另一条路——「可控口播带货」：**
>
> - 支持文本 / 图像 / 视频 / 音频四模态输入，商家能把商品图直接转成展示视频
> - 支持**绝对秒数时间轴**控制，可以直接指定「0-3 秒 Hook、3-7 秒卖点、7-11 秒规格、11-15 秒引导下单」
> - 中文口播与字幕同步
>
> 带货视频的结构是固定的（Hook → 卖点 → 规格 → CTA），H3 的时间轴控制让这套结构第一次能被 prompt 直接指定，而不是生成完再剪。
>
> **两者的差异决定了选型**：同一个时间窗口，Seedance 2.5 押的是长叙事和多主体，H3 押的是可控口播和电商结构。我们要做的是 ______，所以主链路选 ______。
>
> ⚠️ 注意两者的时间表达方式互相冲突（H3 用绝对秒数，Seedance 2.0 系禁用秒数只能用镜头序号），**换模型时 Prompt 要重写**。

**写法上的三条硬要求：**

1. **必须写清「在此之前为什么不行」。** 这是挡「为什么现在做」追问的关键，也是最容易漏的一句。落到参数上讲——「15 秒装不下叙事」比「以前效果不好」有力得多。
2. **必须写能力边界**（现在做不到什么），并据此裁剪本期范围。把限制写出来，「为什么不做 XX」就变成共识，而不是临场解释。
3. **能力阈值要引官方发布说明**，不要引二手解读。二手解读经常把「支持」写成「做得好」。

**能力边界的参考写法：**

> 即便是 2.5，官方也说明在**复杂运动的物理合理性、极多主体交互场景的稳定性**上仍有提升空间。
> 所以本期只做「单主体 + 中低动态」的场景，多人打斗、剧烈运动不在范围内。

---

#### 收口：把两侧接起来

市场层最后必须有一句把供需两侧连起来的话，否则前面的调研是两段互不相干的材料：

> 商家一直想要带货视频（需求侧：找达人拍一条 X 元、周期 Y 天，中小商家上新频率根本覆盖不起），
> 但直到 H3 支持时间轴控制和中文口播同步（供给侧），「用商品图直接生成结构完整的带货视频」才第一次做得成。
> **在此之前，AI 只能生成氛围片，带货视频的固定结构靠模型自由发挥拼不出来。**

### Phase 2 · 团队层：放在哪、会不会打架

**用户提供了内部资料就写，没提供就整节跳过**，只留一行：

> ⚠️ 本节缺少内部资料（现有功能数据 / 用户反馈），以下位置判断为公开信息推断，建议补齐后再定稿。

要回答三个问题：

**Q1. 新功能插在现有产品链路的哪个位置？从哪个入口进？**

**Q2. 会不会和现有功能打架？** 这是最实际的风险，列一张表：

| 打架方式 | 具体表现 |
|---|---|
| 抢入口 | 两个功能抢同一个坑位，老功能数据下滑 |
| 认知混淆 | 用户分不清「智能剪辑」和「一键成片」的区别 |
| 能力重叠 | 解决同一个问题，维护成本翻倍 |

参考写法：

> - **能力差异**：模板是固定坑位填素材，做不到根据素材内容编排故事线；这个功能是基于内容生成叙事
> - **用户分层**：模板服务「有明确成品预期」的用户，这个功能服务「有素材但不知道怎么剪」的用户
> - **入口**：不抢模板入口，独立入口并行
> - **上线后要盯**：模板功能的使用量会不会下滑

最后一行「上线后要盯什么」最有价值——它把一个「可能有风险」变成了「有人负责观察」。

**Q3. 我们有什么别人没有的条件？**（数据、用户规模、现有链路的衔接优势）

### Phase 3 · 用户层：别写抽象用户

❌ 反面写法：

> 用户在剪辑视频时觉得麻烦，希望有更高效的方式。

这句话没有场景、没有具体动作、没法验证。

✅ 正确写法：**至少拆 2-3 个角色**，每个角色写「什么情况下 → 遇到什么 → 结果是什么」，结果尽量写到「**因此没有发生什么**」：

> **角色 A：有素材但不会剪的普通用户**
> 场景：旅行回来手机里 50 段素材，想发条 vlog
> 障碍：不知道从哪段开始剪、不知道配什么文案、套模板和素材内容不搭
> 结果：**素材在相册里躺着，最后什么都没发**
>
> **角色 B：会剪但缺创意的创作者**
> 场景：日更压力下要快速出多条
> 障碍：操作没问题，但每天想文案和结构很耗精力
> 结果：产出频率受限于创意，不是受限于剪辑速度

写完这几个角色往往会发现，**它们要的其实是几个不同的产品**，方案设计时就不会在几种诉求之间摇摆。

**痛点的深浅，决定了机会的大小：**

| 层次 | 举例 | 信息量 |
|---|---|---|
| 表层 | 「操作太麻烦」 | 几乎所有产品都能这么说，没有信息量 |
| 中层 | 「要跳 5 个页面才能换一张图」 | 能指向具体优化 |
| 深层 | 「因为麻烦，用户直接放弃了，素材永远躺在相册里」 | **这个才指向真正的机会** |

深层痛点有个特点：**它描述的是「没有发生的事」**。而没有发生的事不在任何数据看板上——用户没进入功能，就不会有埋点。所以这类痛点只能靠用户访谈或自己观察，光看数据看不到。

**有内部资料时**，从访谈记录、用户反馈里抽取证据，每条痛点后面挂一句原始引用。
**没有资料时**，基于场景推断，并在该条后面标 `（推断，待访谈验证）`。

### Phase 4 · 竞品层：推动机，不是列功能

❌ 功能对照表（竞品 A 有什么、竞品 B 有什么）只有信息，没有结论。

**这一层同样必须联网调研：**

| 调研动作 | 怎么做 |
|---|---|
| 找竞品 | 搜索「{品类} 产品 对比」，或去应用商店搜同类功能 |
| 拿事实 | 打开竞品官网 / 版本发布说明 / 体验文，确认它的具体设计选择（入口位置、一次生成几个、是否收费） |
| 看用户评价 | 搜「{竞品名} 难用 / 吐槽 / 对比」，从差评里找它主动放弃的地方 |

**写法：推演他们为什么这么设计。**

> **竞品 A**：把 AI 剪辑放二级入口，且默认只生成 1 个结果
> **我猜的动机**：单次成本高，1 个结果是成本控制；放二级入口说明他们对效果没信心，不愿意用主入口流量冒险
> **对我们的意义**：如果我们要放主入口，得先把成功率做到某个水平；生成多个候选会明显推高成本，要算一下值不值
>
> **竞品 B**：只做模板套用，不做内容理解
> **我猜的动机**：模板成本极低、结果可预测，是稳妥的选择
> **他们放弃了什么**：处理不了「素材和模板不匹配」的情况
> **我们的机会**：这正是我们要打的——基于内容生成叙事，而不是把素材塞进固定坑位

规律：**差异化最好建立在「竞品主动放弃的地方」，而不是「我们想做得更好」。** 后者只是愿望，前者是判断。

**每段竞品分析后面必须有一句「所以我们的选择是」。** 没有这句的分析直接删掉。

### Phase 5 · 收口 + 组装 + 自检

**收口：为什么必须用大模型。**

这是 AI 需求文档和普通需求文档最不一样的一节，也是被问得最多的。

❌ 「传统方案不够智能」——没有任何信息量。
✅ **说清传统方案在结构上做不到什么**：

> **模板 + 图层方案的结构性问题**：
> 模板的本质是「预设固定坑位，把素材填进去」，这意味着：
> - 坑位数量和顺序是**写死的**，没法根据素材实际内容调整
> - 没法判断「哪段素材更适合放开头」
> - 没法根据画面内容生成匹配的文案
>
> **核心矛盾是：模板不理解素材「讲了什么」，所以没法编排「怎么讲」。**
> 而用户要的恰好是「帮我把这堆素材讲成一个故事」，这需要内容理解能力——这是模板在结构上不具备的，**不是做得不够好**。

「不是做得不够好，是结构上不具备」是关键句。

**再主动说清楚哪里不用大模型：**

> 需要说明的是，这条链路不是全都靠大模型：
> - **片段边界判断**：比较机械的判断，小模型就够，成本是大模型的 1/10
> - **字幕排版、转场渲染**：规则可以完全覆盖
> - **素材格式校验**：普通工程手段
>
> 只有「内容理解」和「叙事编排」是大模型不可替代的。

主动划出不用大模型的边界，说明你在算成本，而不是在追技术热点。

**组装输出**：按 [输出格式](#输出格式) 拼成完整章节。
**自检**：过一遍 [自检清单](#自检清单)，不通过的项要么补，要么在输出里标出来。

## 各层最容易犯的错

| 层 | 常见错误 | 改法 |
|---|---|---|
| 市场层 | 只写模型能力升级（有锤子找钉子） | 补需求侧：有多少人正在用笨办法做这件事、手工成本是多少 |
| 市场层 | 只写「这需求一直都在」 | 补供给侧：哪个版本、哪个参数变了，让它第一次做得成 |
| 市场层 | 能力写成「大幅提升」 | 落到参数级：15 秒 → 30 秒、支持 30 图参考、支持时间戳编辑 |
| 市场层 | 引二手解读当官方结论 | 引官方发布说明；二手解读常把「支持」写成「做得好」 |
| 市场层 | 供需两侧各写一段，不接起来 | 末尾补一句「用户一直想要 X，但直到 Y 才做得成」 |
| 市场层 | 只写能做什么，不写不能做什么 | 补能力边界，并据此裁剪本期范围 |
| 团队层 | 不写会不会和现有功能打架 | 列打架方式表 + 写「上线后要盯什么」 |
| 用户层 | 写一个抽象用户 | 拆 2-3 个角色，写场景 → 障碍 → 结果 |
| 用户层 | 痛点停在「操作麻烦」 | 推到「因此什么事没有发生」 |
| 竞品层 | 列功能对照表 | 推动机，每段收一句「所以我们的选择是」 |
| 收口 | 说传统方案「效果不够好」 | 说它在结构上做不到什么 |
| 收口 | 全链路都要用大模型 | 主动写出哪些环节不该用 |

## 自检清单

- [ ] 把行业名换成别的领域，这段话还成立吗？（成立 = 写太泛，重写）
- [ ] 市场层供需两侧都写了吗？（只有能力 = 有锤子找钉子；只有需求 = 答不了「为什么去年不做」）
- [ ] 需求侧写到「用户现在用什么笨办法、成本多少」了吗？（只写市场规模不算）
- [ ] 供给侧的能力写到参数级了吗？（「大幅提升」不算，要写 15 秒 → 30 秒这种）
- [ ] 模型能力引的是官方发布说明，而不是二手解读吗？
- [ ] 市场层写清了「在此之前为什么不行」吗？
- [ ] 有那句把供需两侧接起来的收口吗？
- [ ] 写了能力边界，并据此裁剪了范围吗？
- [ ] 团队层说清了会不会和现有功能打架，以及上线后盯什么吗？（无资料是否已标注跳过）
- [ ] 用户至少拆了 2-3 个角色，而不是一个抽象用户吗？
- [ ] 痛点写到了「因此什么事没有发生」这一层吗？
- [ ] 竞品层每段都有「所以我们」吗？
- [ ] 竞品层的事实（入口位置、生成数量、是否收费）是查证过的，还是凭印象？
- [ ] 收口论证的是传统方案「结构上做不到」，而不是「效果不够好」吗？
- [ ] 主动写了哪些环节不用大模型吗？
- [ ] 所有标为「假设 / 推断」的条目都显式标出来了吗？

## 我还没搞清楚的

- **竞品动机的推演基本靠猜**，我没有验证过猜得对不对。公开信息只能看到「它这么做了」，看不到「它为什么这么做」。有没有更可靠的方法？
- **用户角色拆到几个合适？** 我拆过 5 个，写完发现方案又开始摇摆了，感觉 2-3 个是上限，但没有依据。
- **市场层的数字引用到什么程度算够？** 引用第三方报告的数字，评审有时会说「这个口径不对」，但自己算又算不准。目前的做法是优先用「手工成本」这类能直接验证的数字，少用行业大盘规模，但没验证过这样是不是真的更容易过。
- **模型发布说明里的能力，和实际可用之间有多大差距？** 官方说「支持 30 张图参考」，不等于 30 张都能稳定生效。写市场层时引官方参数，但真正排期前应该自己跑一轮验证——这一步我还没形成固定动作。
